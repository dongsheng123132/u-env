## 0. 一句话

**代码定义软件做什么，本境定义软件在哪个世界里必然能工作。**

短期做「Windows 环境医生」，中期做「故障重现网络」，长期做「软件运行世界的协议与操作系统层」。

---

## 1. 定位：抢的是入口，不是概念

纯协议传播不动。开发者不会为一个新名词装工具，但会为下面这些问题装：

```
为什么我的 Tauri 打包失败？
为什么别人电脑能跑，我的不行？
为什么 AI 改完代码还是编译不过？
为什么 WebView2 / Rust / Node / Windows SDK 总是冲突？
为什么 CI 能过，本地不能过？
```

所以第一句传播语是：

> **一条命令找出 Windows 项目为什么跑不起来。**
> `irm u-king.org/uenv | iex` → `uenv doctor`

协议藏在工具里。等工具有人用，再把协议独立出来。

### 明确不做（第一年）

- ❌ 不做另一个 Docker / DevPod / Nix
- ❌ 不做虚拟机管理器
- ❌ 不真的做一个操作系统（ShadowOS 是第 3 年的事）
- ❌ 不做云端服务（前 60 天）
- ❌ 不做 GUI（PodApp 后接）

### 空位（竞品扫过一遍后剩下的）

| 竞品 | 他们做的 | 留下的空位 |
|---|---|---|
| DevPod / Flox / Daytona | 创建一个标准环境 | 不理解**已有的坏环境** |
| WinGet Configuration | 声明机器期望状态 | 不做诊断、不做差异、不做故障重现 |
| WinApp CLI（微软） | Windows App 的**动作**工具 | 不做环境本体 |
| Nix / Bazel | 可复现**构建** | 不覆盖 Windows 桌面运行态与故障现场 |

> 我们的空位：**理解任意 Windows 环境，并把出错现场转换成可重现对象。**

## 2. 分层与命名（只留四个品牌，不再新增）

```
本境协议 Origin Environment Protocol (OEP)     ← 标准，永久开放
           │
           ▼
       u-env 开源引擎 (CLI + SDK)              ← 入口，Apache-2.0
           │
     ┌─────┴─────┐
     ▼           ▼
 u-rescue      U-King                          ← 平台 / 分发
故障协作平台    安装与分发入口
     │
     ▼
 ShadowOS                                      ← 长期环境运行时
```

与既有协议的关系：

| 协议 | 回答的问题 |
|---|---|
| **本象协议** | 这个对象本来是什么 |
| **影核协议** | 这个对象能够做什么 |
| **本境协议** | 这个对象在什么条件下能够正确存在和运行 |

> 本象保存对象，影核保存动作，本境保存世界。
> 一象多投影，一核多界面，一境多环境。

## 3. 工程决策（已定，不再讨论）

| 项 | 决定 | 理由 |
|---|---|---|
| **语言** | Rust（workspace，多 crate） | 环境医生**不能依赖被诊断的运行时**——用 Node 写的工具没法诊断「你的 Node 坏了」。单 exe 可 `irm \| iex` 一行分发，无前置依赖 |
| **MSRV** | 1.88（本机 stable = 1.88.0，另装 1.95） | 已验证本机 `cargo 1.88.0` 可构建 |
| **目标平台** | `x86_64-pc-windows-msvc` 优先，`aarch64` 次之 | 主战场 |
| **许可** | 代码 Apache-2.0（含专利授权）；协议与文档 CC BY 4.0 | 比 MIT 更适合做标准生态 |
| **默认行为** | 全部只读；任何写操作必须 `--dry-run` 可预演 + 可回滚 | 第一版**绝不**默认改注册表 / 删软件 |
| **输出** | 人读 + `--json`（AI 读）双模，见 `docs/10-架构与数据模型.md` §7 | u-env 本质是「给 AI 用的本地 API」 |
| **仓库** | 本目录 `D:\uking编程\本境协议`，git init 后推 GitHub | |
| **依赖纪律** | 只允许：clap / serde / serde_json / sha2 / anyhow / thiserror / winreg / chrono；新增依赖需说明理由 | 基础设施工具不能有依赖地狱 |

## 4. 短线：90 天

### 阶段一（第 1-14 天）：真能发现问题的 CLI

只支持三类项目：**Tauri → Electron → Node.js Windows 桌面**。
暂不碰 Python / Java / 游戏 / 驱动 / Android。

命令：`uenv scan` · `uenv doctor` · `uenv report`

必测项目（完整清单见任务包 T1/T2/T3）：
Windows 版本与 Build · x64/ARM64 · PowerShell 版本 · PATH 重复与污染 · Node/npm/pnpm/bun · Rust/rustup/cargo · VS Build Tools · Windows SDK · WebView2 Runtime · Git · WSL 状态 · Developer Mode · Long Path · 项目在 C:\/OneDrive/WSL/网络盘 · 端口占用 · 代理环境变量 · 杀毒拦截 · lockfile 状态 · 声明版本与实际版本差异

输出三份：`report.md`（人）· `report.json`（AI）· `environment.origin.json`（协议对象）

> **验收：拿自己的 10 个 Windows 项目跑，发现 ≥30 个真实环境问题，其中 ≥10 个给出有效修复建议。**

### 阶段二（第 15-30 天）：指纹与差异

`uenv fingerprint` · `uenv diff a.json b.json` · `uenv fix --dry-run` · `uenv fix`

修复三档安全等级：`safe`（可自动）/ `confirm`（需确认）/ `manual`（只给说明）。
所有写操作：支持 `--dry-run` · 保存修改前状态 · 生成回滚命令 · 记录执行轨迹。

> **验收：用户能把一台坏机器和一台好机器做环境比较。这是第一个可公开发布的版本。**

### 阶段三（第 31-60 天）：故障舱 EnvCapsule —— 最有区分度的功能

```
uenv capsule create        → bug-2026-08-05-001.uenv
uenv capsule inspect / compare / replay
```

舱内结构：`manifest.json` `environment.json` `project.json` `actions.json` `logs/` `screenshots/` `traces/` `reproduce.ps1` `redaction.json`

`replay` 第一版只做**投影生成**，不自己造底层：
WinGet Configuration · PowerShell 初始化脚本 · Dev Container · Windows Sandbox `.wsb` · GitHub Actions workflow

> **验收：用户能把一个 Windows Bug 变成可上传、可比较、可重现的文件。这是最容易传播的 Demo。**

### 阶段四（第 61-90 天）：社区与数据飞轮

发布四件事：① `u-env` CLI ② 本境协议草案 `OEP v0.1`（从真实案例归纳，不是先发明理论）③ `rescue.u-king.org` ④ Windows AI 开发稳定性榜单

首批支持矩阵：

| 框架 | 扫描 | 诊断 | 修复 | 故障舱 | 重现 |
|---|---:|---:|---:|---:|---:|
| Tauri | ✅ | ✅ | ✅ | ✅ | Beta |
| Electron | ✅ | ✅ | 部分 | ✅ | Beta |
| Node.js | ✅ | ✅ | ✅ | ✅ | 部分 |
| WinUI/.NET | Beta | Beta | - | ✅ | - |

WinUI/.NET/Rust 的打包、身份、证书能力**直接把微软 WinApp CLI 当 Adapter 接进来**，不自己复制。

## 5. 中线：3-12 个月

**3-6 个月：从工具变成系统**

1. **Adapter 插件系统** —— `adapters/{tauri,electron,winui,dotnet,node,rust,python,wsl,winget,winapp,devcontainer,windows-sandbox}`，任何人可贡献
2. **Rule 规则仓库** —— 每个 Bug 转成可执行 YAML 规则：
   ```yaml
   id: rust-duplicate-toolchain
   when: count(path.executables.cargo) > 1
   severity: warning
   explain: { zh: "PATH 中发现多个 Cargo，可能使用了错误工具链。" }
   fix: { safety: confirm, action: normalize-path }
   ```
3. **Agent Skill** —— 让 DeepSeek / Claude Code / Codex 写代码前自动跑 `uenv doctor --agent`，构建失败后自动 `uenv capsule create --from-last-failure`
4. **u-rescue 公共故障库** —— 面向 Windows 环境问题的结构化 Stack Overflow：问题特征 / 环境指纹 / 复现步骤 / 差异原因 / 修复动作 / 验证结果

**6-12 个月：商业化**（见 §7）

## 6. 长线：1-3 年

**第 1 年 · 环境 Git**：`uenv init/status/diff/commit/checkout/bisect`
其中 **`uenv bisect` 可能是真正的杀手级功能**——自动二分查找：究竟是哪次 SDK 更新、PATH 修改、系统更新或依赖变化把软件搞坏的。

**第 2 年 · 环境因果图**：从「有什么不同」升级到「哪个变化最可能导致当前问题」
```
Windows 更新 → WebView2 更新 → 渲染行为变化 → Tauri 白屏
```
AI 的价值不是生成几条 PowerShell，而是结合历史故障数据做因果判断。

**第 3 年 · ShadowOS**：项目声明本境 → ShadowOS 自动选执行环境（WSL/Sandbox/Container/VM/Native）→ 执行影核动作 → 输出验证结果。人不再关心应用跑在哪里。

## 8. 怎么让别人一起开发

把贡献拆到足够小 —— 一个新贡献者只需完成**其中一种**：

| 入口 | 门槛 | 例子 |
|---|---|---|
| **Detector** | 写一个文件，实现一个 trait | 检测 WebView2 版本 / 长路径开关 / 代理变量 |
| **Rule** | 写一个 YAML | 两个 Node 共存造成 npm 调用错误 |
| **Adapter** | 支持一个框架 | Flutter Windows / Godot / Unity / Qt / Python Desktop |
| **Capsule** | 提交一个脱敏真实故障案例 | 无需写代码 |
| **Recipe** | 提供一个可工作的环境模板 | 无需写代码 |

宣传语不是「请帮我们开发一个伟大的协议」，而是：

> **提交一个你遇到过的 Windows Bug，让它以后永远不再困扰其他人。**

**飞轮**：开发者遇 Bug → u-env 生成故障舱 → 上传 u-rescue → AI/社区找到原因 → 修复转成公开 Rule → 下一个用户自动发现 → 规则库越来越强。

护城河不是 CLI 代码（能抄），是：Windows 环境图谱 · 真实故障胶囊 · 故障↔差异映射 · 修复成功率 · Adapter 生态 · 协议采用量。

## 9. 指标（不要只盯 Star）

1. 首次成功构建时间（新机器从 clone 到 build 成功）
2. 诊断命中率（真实问题中被发现的比例）
3. 自动修复成功率
4. 故障舱重现率（另一台机器能否重现）
5. 平均修复时间 MTTR
6. 规则复用次数（一条新规则帮了多少后来人）

**90 天目标**：100 个真实 Windows 项目 · 500 份环境报告 · 100 份脱敏故障舱 · 50 条有效规则 · 20 名外部贡献者 · ≥30% 自动诊断命中率 · ≥60% 已知案例重现率

## 10. 现有产品怎么借力抢先

- **U-King**：装完 AI 编程工具后自动跑「开发环境体检」→ 现有用户成为第一批数据与测试来源
- **u-rescue**：从「Codex Bug 收集工具」升级为「AI 开发故障重现平台」，Codex/DeepSeek/Claude Code 都只是入口之一
- **影核协议**：提供可验证动作（build/run/open-window/save/package/smoke-test），故障舱不只存环境，还存动作执行结果
- **本象协议**：保存项目/环境/故障/动作/输出对象之间的关系
- **PodApp**：后期给 u-env 做 GUI 舱（差异选择 / 修复勾选 / 脱敏 / 上传确认 / 重现查看）
