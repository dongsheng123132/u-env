# 12 · 与 U-King `envfp` 的口径对账

> 日期：2026-08-08 · 状态：**对账已做，尚未拍板归属**
> 起因：同一件事实（「这台 Windows 有什么炸点」）在本境和 U-King 各有一份实现。
> 宪法第 8 条：**同一事实存在几份就会漂移几份。**

## 0. 为什么现在做

2026-08-08 当天已经有两个案例证明「漏掉的那一份不会报错」：

- U-King 的 `identity.rs` 是全仓十六个模块里**唯一**不认沙箱变量的，
  于是它的写动作静默写到真实机器上 —— 没有任何报错；
- 影核判分器里三条打分逻辑**无人看守**，主指标可以被写死成 0 而自测全绿。

环境探测是第三个候选：两份实现、都在跑、都在给客户建议，**但从没有人把它们摆在一起看过**。

## 1. 方法：同一台机器、同一时刻，两边都真跑

不读代码猜，直接取真实输出（开发机，Windows 11 22631，i9-12900H/64G）：

```bash
# 本境
uenv doctor --project . --agent          # → 3 条 findings
# U-King
u-king-mini.exe --envfp                  # → 23 个事实位
u-king-mini.exe --metrics-report 7        # → 建议引擎 1 条
```

## 2. 结果：重叠只有一条，而且口径不同

| | U-King 建议引擎 | 本境 uenv doctor |
|---|---|---|
| 产出条数 | **1** | **3** |
| 内容 | `defender_rt`「Defender 实时防护开着，装包会明显变慢」 | `rust.multiple-cargo-in-path`(warning)<br>`fs.project-path-non-ascii`(warning)<br>`security.defender-scans-project`(**info**) |

**同一台机器，一个说 1 个问题，一个说 3 个。** 而且唯一重叠的那条，两边的判据和严重度都不一样。

## 3. 三处具体漂移

### ① 同一事实，两个判据、两个严重度（Defender）

| | 判据 | 定级 |
|---|---|---|
| U-King `defender_rt` | 实时保护**开没开**（布尔） | 出现在建议里 |
| 本境 `security.defender-scans-project` | 开着**且排除项没覆盖项目目录** | **info**（最低） |

本境的判据更准：Defender 开着但已把项目目录排除的机器，**不该被打扰**。
U-King 那个布尔会对所有开着 Defender 的机器一律建议 —— 而那是绝大多数机器。

### ② 名字几乎一样，量的却是两个东西（非 ASCII 路径）

| | 实际测量 | 本机结果 |
|---|---|---|
| U-King `path_nonascii` | `!home_dir.is_ascii()` —— **用户家目录** | `false`（`C:\Users\<user>`） |
| 本境 `fs.project-path-non-ascii` | **项目路径** | `warning`（路径含中文） |

**两边都没错，但合起来会骗人**：U-King 报「`path_nonascii: false`」，
而它自己的项目目录 `u-king简化版-u盘版本` 就是中文的。
U-King 的工作台会话工作目录同样可以落在中文路径上 ——
**这条维度 U-King 完全没有覆盖**，而中文路径是它历史上最贵的一类装机故障
（pip.ini 按 cp936 读、装不上 Hermes，跨 4 个版本 5 条报告）。

### ③ U-King 缺了对它自己最致命的那一条（WebView2）

本境有 `webview2.missing` 规则（本机已装，故跳过），
U-King 的 23 个指纹位里**一个字都没有 WebView2**。

而 U-King 在没装 WebView2 的机器上的表现是**静默假死** ——
进程活着、任务栏有图标、界面永远不出来，调度线程/设备 Key/metrics 全没起，零报错。
**它自己最致命的环境依赖，没进它自己的环境指纹。**

## 4. 谁该是真源：三条路，各有代价

| 方案 | 好处 | 代价 |
|---|---|---|
| **A. U-King 直接依赖 `uenv-scanner` crate** | 探测器只剩一份，27 个 detector 白拿（含 WebView2） | 引入 `winreg`/`chrono`/`sha2`/`anyhow`。U-King 是 U 盘产品，Cargo.toml 只有 serde/portable-pty/blake3/flate2/tar，`opt-level="z"+lto` 压到 8.6MB —— **体积增量必须先实测再决定，不能拍脑袋** |
| **B. 语义对齐 + 自动对账**（建议先走这条） | 不动依赖树；同一事实用同一 `rule_id` 和同一判据；漂移**变响**而不是变静 | 实现仍是两份，仍会漂移，只是漂移会被抓到 |
| **C. 内嵌 uenv.exe 当 sidecar** | 零耦合 | 违反 U-King「两层、没有 sidecar」的既定架构取舍 |

**建议：先 B，A 留作选项但要先量体积。**

B 的具体含义 —— **本境拥有「事实的定义」，U-King 是实现方之一**：

1. 本境的 `rule_id` 是**唯一命名真源**。U-King 的指纹位映射到 rule_id，
   一对一或明确声明「本实现不覆盖」；
2. 判据不一致时**以本境为准**（它的判据更细，例如 Defender 那条）；
3. 加一条**对账跑道**（`tools/crosscheck-uking.mjs`），
   同机跑两边、把差异打印出来；覆盖缺口如实列出，不假装齐平。

这和影核那条「**可以缺，不可以瞒**」是同一条原则：
U-King 不覆盖某个维度完全可以，但**必须说出来**，而不是让一个 `false` 冒充「这台机器没问题」。

## 5. 边界

- 本次只对了**开发机一台**。开发机有代理、有完整工具链，不能代表客户裸机 ——
  三处漂移是**结构性**的（判据不同、量的东西不同、维度缺失），不依赖这一台的具体数值；
  但「两边条数 1 vs 3」这个比例不要外推。
- 两者**产品目的本来就不同**：`envfp` 是非隐私指纹（24h 缓存、给建议引擎和跨机聚合用），
  `uenv doctor` 是诊断 + 可回滚的修复建议。**目的不同不妨碍事实同源** ——
  该统一的是「什么算一个炸点、判据是什么」，不是把两个产品合成一个。
