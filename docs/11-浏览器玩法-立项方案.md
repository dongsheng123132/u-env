> 状态：草案 v0.1 · 2026-08-07 · **开放**（2026-08-26 复审：随 u-env 仓库公开发布；下方「内部文件（先不开源）」为当时决策的历史记录，保留不改）
> 判定：**做**。依据 + 架构 + 阶段计划 + 边界如下。

## 0. 一页摘要

**做。** 但不是做「又一个浏览器 agent」——那是当前最挤的赛道（browser-use / Kimi WebBridge / Codex 桌面级 Computer Use），必输。做的是**浏览器域的本境/本象方言**：把 uenv（本境协议）的 `scan → fingerprint → diff → doctor` 机器，和本象协议的**约束谓词 + 证据链 + 影核 parity** 一起搬到浏览器上，让任何 agent 在**本地真实登录态浏览器**里做的每一步动作，都是**经约束校验、带证据链、可回放**的语义事务。

一句话定位：

> 别人让你 AI 能点浏览器；我们让 AI 点的每一步都有约束、有证据、能证明效果。

三行理由：
1. **Web 方言已登记、未实现**——本象协议 `docs/03-协议草案-v0.1.md:327` 已登记「Web | DOM 与运行态」方言，`docs/04-架构设计.md:139-151` 已写好 Set-of-Mark 操作闭环，`tools/autopublish` 已在用浏览器会话当执行器。这是**补全一个已登记方言**，不是另起炉灶。
2. **两条资产线都齐了**——本境 uenv（Rust）有完整的指纹/diff/诊断机器，本象（JS）有领域无关的 10 种约束谓词 + append-only 证据链。浏览器是这套体系第一次能让**四层同时观察同一个实体（一个网页）**的地方。
3. **是浏览器，不是第 4 个项目**——它是小说/CAD/长上下文三件实事的**通用落地载体和最大规模试验场**。立项为独立线，但价值始终是喂回三件实事。

## 1. 定位与差异化

### 1.1 与五类方案的区隔

| 方案类别 | 代表 | 他们在执行层结束 | 我们多一层 |
|---|---|---|---|
| 传统自动化 | Playwright/Puppeteer/Selenium | 选择器失效就崩 | 选择器=约束，破了→检测→重验证→留证 |
| 开源 AI agent 框架 | browser-use/Stagehand/Skyvern | 看页面→决策→动作，无验证闭环 | 每次动作前/后快照 diff + parity 校验 |
| 云端浏览器 | Browserbase/Browserless/Steel | 托管实例，非日常浏览器 | 本地真实登录态 + 证据链 |
| 厂商 Computer Use | Codex/Claude 扩展 | 深度绑定自家生态 | Agent 通用（Claude Code/Codex/Hermes） |
| 本地桥接 | **Kimi WebBridge** | 桥接真实浏览器，但**无协议层** | 在桥接之上加约束+证据+parity 协议 |

Kimi WebBridge 证明了「本地真实浏览器桥接」这条路线被市场认可。**它止步于「桥」，我们做的是桥上的「协议」**——这也是研究（`本象协议/docs/05-生态对照.md`）反复确认的市场空位：写侧事务语义 + 约束校验 + 证据链的组合层，无人做。

### 1.2 我们不做的事（先立边界）

- 不重造浏览器自动化引擎——Playwright/CDP/扩展只当**执行器**，由影核负责路由与回退。
- 不做无痕/隔离浏览器的默认路线——默认走**本地真实登录态**（数据不出本机），无痕只作可选沙箱。
- 不承诺选择器永久有效——选择器是约束不是承诺，破了走「检测→重验证」。
- 不把证据链做成私有二进制——沿用本象 `provenance/history.jsonl` append-only 格式。

## 2. 架构

### 2.1 四层映射

| 协议层 | 仓库/载体 | 浏览器里的对应物 |
|---|---|---|
| 本象（对象层） | 本象协议 | 页面 = 对象图：`page` / `frame:*` / `el:*` / `form:*` / `field:*` / `net:*` / `console:*` |
| 影核（动作层） | 本象协议 | 语义动作：`click` `type` `submit` `navigate` `wait`，路由到 CDP/扩展执行器 |
| 叠象（证据层） | 本象协议 | 快照 diff + parity 校验 + append-only 动作日志 + 截图证据 |
| 本境（环境层） | **本境协议 uenv（本仓库）** | 浏览器/Profile/登录态/扩展/页面的 scan→fingerprint→diff→doctor |

### 2.2 两线合一

```
                     ┌────────────────────────────────────┐
  线 B 操作 (act)     │                                    │
  agent 意图 → 语义动作 → CDP 执行 → 动作后快照              │
                              │ diff(before, after)       │
  线 A 诊断 (webdoctor)        ▼                           │
  页面 scan → fingerprint → 规则 → Findings+修复建议 ──→ parity 校验 ─→ 证据日志
                              ▲                           │
                              同一套快照/指纹/diff 机器      │
                     └────────────────────────────────────┘
```

- **线 A（webdoctor）**是 uenv 的自然延伸：把「扫描开发环境」换成「扫描浏览器+页面」。纯复用，几乎零协议设计风险。
- **线 B（act + parity）**是差异化本体：动作前/后快照 → diff → 对照声明意图做 parity 校验 → 记入证据链。这一步是「约束+证据+parity」第一次真正跑到浏览器上。
- 两条线共享同一套**快照/指纹/diff** 机器，所以合起来做成本只比单做 A 高约一半，收益完整。你的选择「A+B 一次做」是对的。

### 2.3 技术家（已定：扩本境 uenv Rust workspace · 2026-08-07）

- 线 A 直接落在本仓库（Rust）：新增 `crates/uenv-web-*` + `adapters/uenv-web`。
- 线 B 的约束谓词：以本象 `spec/conformance/vectors/03-constraints.json`（10 种谓词的一致向量）为**契约源**，在 Rust 里实现一个最小求值器并通过同一套向量——**数据即契约，防两份实现漂移**（shadowbench 自带编译器副本漂移的技术债教训）。
- agent 入口：先 CLI（沿用 uenv `output.rs` 的 `--agent` 契约：stdout=数据/stderr=日志/JSON 信封），后续按需加 MCP server。
- 若 Gate 0 通过、决定开源时，可再拆独立 repo；当前先长在本仓库，保复用与速度。

## 4. 差异化核心：约束 + 证据 + parity 的浏览器形态

协议 10 种约束谓词**全部直译可用**，无需发明新谓词（本象 `docs/03` + 一致向量已证实）：

| 场景 | 谓词 | 示例 |
|---|---|---|
| 登录失败校验 | `equals` | `el:error-msg.visible == true` |
| 提交后跳转 | `equals` + `not_equals` | `page.url == /dashboard`，`page.url != /login` |
| 字段生效 | `exists` + `range` | `field:total-price.value >= 0` |
| 不该动的别动 | `unchanged` | 操作 A 不应改动 `el:sidebar.*` |
| 数量对账 | `count` | 购物车行数 == 结算清单行数 |
| 请求落库 | `contains` / `not_contains` | `net:*.url` 含 `/api/order`，不含 `/api/order?dryRun` |

**parity 校验**：每个语义动作声明意图（`assertions`），动作后跑 diff + 约束，全部通过才算「做到」，否则把 violations 回传 agent 重做——这正是本象 `commit-compiler` 的「把说到和做到分开记账」，落到浏览器上。

**证据链**：每次动作记录 `{action, before_fp, after_fp, diff, constraints_checked, passed, screenshot, tx}` 到 append-only 日志，`web why <field>` 可回答「这个页面值凭什么是这个值」。这就是浏览器版的「做完能证明、出问题能回放」。

## 5. 阶段计划

### Phase 0 · Gate 0 实验（先验证，再立项定案）｜ ~1-2 周

按项目自己的方法论（ShadowBench 决策规则：本象包**明显优于**纯文本/截图才立项）。**两个任务都跑**（已定 · 2026-08-07）：

- **任务 1**：「填表 → 校验总价正确 → 提交 → 验证跳转」全流程，三臂对比：纯文本 / 纯截图 / 快照+约束+证据包。最能直接验证线 B「约束+证据+parity」的价值。
- **任务 2**（现成的）：`benchmark/README.md:39`「找出网页截图中对应的可操作对象」。与现有 ShadowBench 体系直接挂钩，可进论文/榜单。

判分教训：**验证类判分只用 qwen-plus**，deepseek-v4-flash 同题判分全判 no（LongMemEval 教训），别走 hermes 判分。

**Go 条件**：快照+约束+证据包在有效效率（正确完成数/(token×延迟)）上显著胜出。

### Phase 1 · 线 A webdoctor｜ ~2-3 周

扩 uenv：浏览器+页面 scan → fingerprint → diff → 规则 → `uenv doctor --web`。首个可用物是「**我的页面为什么这样**」——能扫任意已开页面，报 console 错/死链/表单态/混合内容，给 Finding+修复建议。

### Phase 2 · 线 B act + parity｜ ~3-4 周

CDP 语义动作层 + 动作前/后快照 diff + 约束求值 + parity 校验 + append-only 动作日志。首个验证场景建议：**在线发布类**（接 autopublish 的既有需求）——「一键发布 X 到 N 个平台，每步留证、失败可回放」。

### Phase 3 · agent 入口 + 全链 demo｜ ~1-2 周

CLI `--agent` 模式（沿用 uenv 输出契约）→ 可选 MCP。demo：在真实登录浏览器里跑一个「操作→校验→留证→回放」全链任务，证明「约束+证据+parity」确实比裸执行多一层价值。

## 6. 边界与风险（docs/08 七要素写法）

| 边界类型 | 声明 |
|---|---|
| `degraded` | 选择器/A11y 树对 canvas/WebGL 页面退化 → 换 DOM 快照 + 视觉证据 |
| `undetectable` | 页面内 JS 校验之外的逻辑错误，确定性检查抓不到 → 交给人/语义验证 |
| `unverified` | 跨浏览器一致性尚未实测（先只保证本机 Chrome/Edge）→ 去测 |
| `lossy` | 页面被重排后截图/快照可能失真 → 回到 DOM/网络源取 |

**两个主要风险：**
1. **SuperWriter 陷阱 #2**——被当成「又一个浏览器 agent」。对策：卖点是协议层（约束+证据+parity+可回放），不是操控能力；Gate 0 用数据钉死差异化。
2. **范围膨胀**——立项独立线，但要守住「浏览器是载体，喂回三件实事」。若 Gate 0 不通过，**只做线 A**（低成本、仍有用），不硬做线 B。
