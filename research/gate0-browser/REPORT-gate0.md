# Gate 0 实验报告 · 浏览器玩法三臂对比

> 日期：2026-08-07 · 状态：**GO（协议层差异化成立）**
> 立项方案：`docs/11-浏览器玩法-立项方案.md` §5 Phase 0

## 1. 方法与装置

| 项 | 设置 |
|---|---|
| 任务 1 | `order-form.html`：填表→校验总价→提交→验证跳转（3 个问题：Q1 理解 / Q2 操作计划 / Q3 验证） |
| 任务 2 | `operable-page.html`：枚举页面全部可操作对象（1 个问题） |
| 三臂 | A=纯文本(innerText) · B=纯截图(PNG) · C=本象包(结构化对象图+约束声明) |
| 执行模型 | deepseek-v4-flash（hermes HTTP 直连，max_tokens 32768，空输出重试） |

| 轮次 | 每格 5 轮独立执行，判分按真值检查点逐项 0/1 |
| B 臂 | **本报告不含**——纯截图需视觉模型执行，本机无就绪视觉通道，待补 |

## 2. 结果

### 任务 1（填表校验流程）——5 轮 × 5 检查点

| 问题 | A 纯文本 | C 本象包 |
|---|---|---|
| Q1 理解（页面是什么/商品/单价/总价） | **100%** | **100%** |
| Q2 操作计划（填哪几行多少/总价多少） | **100%** | **100%** |
| Q3 验证（提交成功的检查点与条件） | **0%** | **96%** |

### 任务 2（找可操作对象）——5 轮 × 6 检查点

| 问题 | A 纯文本 | C 本象包 |
|---|---|---|
| Q1 枚举（6 个可操作对象：select/input/3 button/a） | **33.3%** | **100%** |

## 3. 解读

**核心结论：约束层让「验证」从不可能变可能。**
- Q3 是判断「提交是否成功」的验证问题。纯文本表示里**没有**提交成功后的语义（文本是初始状态的 dump），模型只能答「无法确认」——5 轮全 0。
- 本象包的 `c:success` 约束把「成功 ⟺ hash=#confirmed ∧ 确认区可见 ∧ 表单隐藏 ∧ 件数=3 ∧ 金额=43」**显式声明在包里**，模型直接据此列出完整检查点——5 轮 96%。
- 这正是立项方案押注的差异化：**写侧事务语义 + 约束校验**。验证知识在包里，不在像素/文本里。

**结构化事实让枚举从 1/3 到 100%。**
- 任务 2 纯文本把按钮/链接/输入框和普通文字混在一起，模型只找到 2/3 的对象（33.3%）。
- 本象包把 `in:* / btn:* / lnk:* / sel:*` 按类型结构化列出，枚举完备（100%）。

**不过度声称**：Q1/Q2 两臂都 100%（平手）——任务简单、纯文本足够时，本象包没有收益。**本象包的胜面集中在「需要不变量/结构化语义」的任务**，不是所有任务。这恰恰是可信的信号，不是通吃。

## 4. 已知限制（如实标注）

1. **B 臂（截图）未跑**——需视觉模型执行，本机无就绪通道。作为对照的缺口，但 A(文本) vs C(包) 已足以支撑差异化结论；截图臂是「执行层基线」，不影响「协议层价值」的判定。
2. **token 效率未体现压缩优势**——fixture 小，纯文本本身只有几百字符，本象包反而输入多 ~2.5 倍（A ~425 in / C ~1180 in）。本象包的压缩优势要在大噪音页面（真实页面文本几千 token）才显现。当前结论是「**准确率**优势」，不是「token 节省」。
3. **n=5 每格**——样本小，未做显著性检验。方向明确、幅度巨大（0→96%、33%→100%），但数值是点估计。
4. **执行模型弱（flash）**——用弱模型都能出这个差距，说明表示本身的信息增益大；但强模型（qwen-plus 执行）下的差距幅度未知。

## 5. Go/No-Go 建议：**GO**

**协议层差异化（约束+证据+parity）在浏览器域成立**，且是在最弱的执行模型上成立的。依据 ShadowBench 决策规则（本象包显著优于纯文本），三条 MVP 候选（本象记忆 MCP / PPT 审阅 / OriginWriter）的同款判据在本实验得到支持。

**但按已定边界收窄立项**：这验证的是「协议层」，不是「又一个浏览器 agent」。下一阶段建议：
- 补 B 臂（视觉执行）——决定执行层基线，可借用 Codex/Kimi WebBridge 或视觉模型通道。
- 上真实复杂页面做 token 效率对照（验证压缩优势）。
- 进入 Phase 1（线 A webdoctor）与 Phase 2（线 B act+parity）时，把本实验的 `c:success` 这类约束直接沉淀为 Web 方言的约束谓词示例。

## 6. 复现

```bash

node render-arms.mjs
# 批量执行（hermes）
node run-gate0.mjs --task task1 --arms A,C --rounds 5
node run-gate0.mjs --task task2 --arms A,C --rounds 5
# 判分（qwen-plus，需 device.json key）
node judge-gate0.mjs task1
node judge-gate0.mjs task2
```
结果 JSON 在 `runs/<task>/results|scores/`，汇总在 `scores/summary.json`。
